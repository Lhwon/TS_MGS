## AI 에이전트

AI 에이전트는 일반 질문에는 대화로 응답하고, 작업 요청에는 필요한 도구를 선택해 조회·편집한 뒤 실제 결과를 확인하여 다음 작업을 이어갑니다. 도구 실패도 관찰 결과로 전달해 인수를 보정하거나 필요한 내용을 질문합니다. 작업 내역은 각 응답에서 펼쳐 볼 수 있으며 편집은 기존 실행 취소 이력에 기록합니다. 노드·경로·포트·도형의 조회와 편집, 설비 모델 제작과 배치, 도면 분석과 배경 편집을 조합할 수 있습니다. 앱이 제공한 도구 범위 안에서 동작하며 임의의 코드나 셸을 실행하지 않습니다.

이미지 첨부는 문맥 제공이며 적용 명령이 아닙니다. “이 도면은 어떻게 보여?”는 읽기 분석으로, “편집 배경으로만 깔아줘”는 Layout Load로, “이 기준으로 경로를 만들어줘”는 실제 노드·경로 생성으로 처리합니다. 배경 적용, 설비 인식, 곡선 생성은 항상 실행되는 고정 순서가 아닙니다. 일반 대화를 할 때는 첨부 도면을 자동 분석하거나 맵을 변경하지 않습니다.

모든 작업은 현재 맵과 첨부·선택 상태에서 확인할 수 있는 정보를 먼저 조회합니다. 필수 정보나 판단 근거가 부족하면 공통 `ask_user` 도구가 채팅에 숫자·단위·텍스트·단일 선택·복수 선택·예/아니요 입력 카드를 표시합니다. 답변은 원래 작업의 도구 결과로 전달하며 최신 상태에서 계획을 갱신해 계속합니다. 선택 정보에는 “아니요, 나중에”를 제공할 수 있고, 채팅 입력창에 자유롭게 답하거나 대기 중 도면을 첨부할 수도 있습니다. 질문 대기 중에는 모델 요청을 유지하지 않습니다. 내부 실행 오류는 정보 부족과 구분합니다.

선택한 노드에는 실제 좌표·범위·중심·연결 경계와 포트 정보가 전달됩니다. `edit_selection`으로 선택 노드·포트·배치 설비를 조회하고 이동·삭제·복제할 수 있습니다. 이동은 상대 거리 또는 선택 중심의 목표 좌표로 계산하며 mm 맵에서는 m 단위도 환산합니다. 노드 복제는 내부 연결과 종속 포트를 함께 생성하고, 삭제는 연결 경로와 종속 포트를 정리합니다. 임의 객체 추가는 기존 `edit_map`을 사용합니다. 여러 종류가 함께 선택되거나 이동 거리·실제 축척이 불명확하면 질문으로 확인합니다. 일반 노드의 연결 그래프 복제를 지원하며 곡선 가상 노드 복제는 별도 곡선 재구성이 필요합니다.

전송한 첨부는 입력칸에서 제거하며 대화 메시지와 작업 참조로 유지합니다. 다음 메시지에 같은 이미지를 자동 첨부하지 않고, 후속 도면 작업에서는 이미 전송한 도면을 참조합니다. 경로 추출은 통로 두께에 비례한 내부 구멍 정리와 선분 단순화로 문자·보간으로 생긴 불필요한 굴곡을 줄입니다.

전송은 연속으로 가능하며 완료·오류·취소 후 입력 상태를 해제합니다. 실행 중 새 메시지를 보내면 이전 요청을 취소하고 현재 맵과 대화에서 이어갑니다. 질문 대기 중 새 메시지는 해당 질문의 답변으로 전달합니다. 새 대화는 이전 요청의 늦은 응답과 이력 복원을 차단합니다.

채팅에는 고정된 mm/px 입력 폼이 없습니다. 정확한 치수가 없어도 가능한 초안과 임시 참고 배치부터 진행하며, 실제 설비 크기나 정확한 정렬에 필요한 경우에만 알고 있는 통로 폭이나 도면 가로 길이를 자연스럽게 질문합니다. “전체 가로가 120미터야”처럼 답하면 앞선 작업을 이어갑니다. 정확한 실제 치수가 확정되지 않은 생성 맵은 초안으로 유지하고 JMAPX나 실제 설비 배치 전에 비율을 확인합니다.

원본 MGS의 **Layout Load**를 편집용 배경 기능으로 제공합니다. 수동 도구에서는 이미지를 드래그해 자르거나 흰 여백을 자동 제거하고 표시 농도, 위치, 회전과 선택적인 실제 가로 길이를 조정합니다. **Show Layout**은 배경만 표시하거나 숨깁니다. 기존 노드·경로를 이동하거나 크기를 바꾸지 않습니다. 배경은 지도 JSON에 포함되며 별도의 .layout.json으로 저장해 다시 열 수도 있습니다. JMAPX에는 배경 영상이 포함되지 않으므로 필요하면 배경 설정을 별도 보관합니다.

도면 인식과 객체 수정은 요청에 따라 도구로 실행하고, 세부 조정이 필요한 경우에만 **도면 편집 도구** 패널을 엽니다. 원본을 구역별로 분석하고 신뢰도와 원본 위치를 보관합니다. 인식 객체는 이름, 종류, 위치, 치수, 회전, 높이와 반영 여부를 수정할 수 있으며 실제 비율을 맞춘 후 포트와 연결된 편집 가능한 3D 모델로 제작합니다. 임시 높이와 검토 대상은 결과에 남깁니다. 곡선은 접선 원호와 MGS 가상 노드로 구성하며 재설정과 실행 취소를 지원합니다. 통로 폭·차량 여유·설비 중첩·연결과 인식 신뢰도를 점검하고 보고서를 저장할 수 있습니다.

도면 인식은 모델의 영상 해석에 기반하므로 누락과 오인식이 발생할 수 있습니다. 원본에 없는 높이·치수·도킹 방향이나 차량 회전 성능을 확정하지 않습니다. 분석 패널의 검토 항목은 운행 승인이나 실제 안전 검증을 대체하지 않습니다. JSON은 원본 참조 영상·인식 객체·수정 상태·자동 곡선 복원 정보를 보관하고 JMAPX는 2D 운행 객체를, 기존 3D 추출은 equipment.json과 map3d.json을 보관합니다.

개발 기본 서버는 `http://192.168.1.161:11434`, 작업 모델은 `gpt-oss:20b`, 도면 비전 모델은 `qwen2.5vl:7b`입니다. Electron 메인 프로세스 또는 Vite 개발 서버가 해당 서버와 통신합니다. 현장 노트북에는 Ollama와 모델을 미리 설치하고 아래 환경 변수로 로컬 서버를 지정한 뒤 앱을 실행합니다. 서버 주소는 사용자 화면에 표시하지 않습니다. 채팅 상단의 모델 아이콘을 누르면 Ollama 설치 모델을 검색하고 선택할 수 있습니다. 선택은 다음 요청부터 적용하고 앱을 다시 열어도 유지합니다. 도구 호출을 지원하는 모델은 맵 작업에 사용하며 도구 미지원 대화 모델은 일반 대화로 응답합니다. 도면 영상 인식 모델은 별도 설정을 유지합니다.

```powershell
$env:TS_MGS_AI_URL = 'http://127.0.0.1:11434'
$env:TS_MGS_AI_MODEL = 'gpt-oss:20b'
$env:TS_MGS_VISION_MODEL = 'qwen2.5vl:7b'
npm start
```

개발 실행도 같은 환경 변수를 사용하며 설정 변경 후 앱과 개발 서버를 다시 실행합니다. AI 기능은 외부 클라우드나 모델 다운로드를 호출하지 않습니다.

## 실행

Node.js 24와 Windows 환경을 기준으로 합니다. Electron main과 preload 변경은 앱 재시작 후 적용됩니다. 이전 브리지로 실행 중인 화면의 지도 저장은 파일 다운로드로 보관하며, 다운로드를 요청한 문서는 자동으로 저장 완료 처리하지 않습니다.

```powershell
npm install
npm run dev
```

- `npm run dev`: Vite + Electron 개발 실행
- `npm run dev:web`: 브라우저 개발 실행
- `npm run format`: 전체 코드 정렬과 줄바꿈 적용
- `npm run format:check`: 코드 형식 검사
- `npm run typecheck`: FSD 경계 및 TypeScript 검사
- `npm run build`: 타입 검사 후 화면 빌드
- `npm start`: 빌드된 화면을 Electron에서 실행 (`npm run build` 선행)

## 구조

- `src/`: FSD 앱 소스 (app/pages/widgets/features/entities/shared)
- `electron/`: Electron 창·preload·파일 입출력
- `packages/map3d/`: TS_MGS와 TS_UI가 공유하는 3D 데이터 계약·검증·설비 생성·포트 위치 해석
- `scripts/dev.mjs`: 개발 서버와 Electron 실행
- `scripts/check-fsd.mjs`: 빌드에 사용하는 FSD 경계 검사

## 지도 화면

2D 화면은 원본 MainWindow.xaml의 File·View·Drawing·Data·Vehicle·Shape·Setting·GRID·Expert / Developer 탭 순서와 상단 리본 130px, Summary 280px, 빠른 작업줄 35px, 하단 로그와 선택 목록 128px, 상태 표시줄 28px 구조를 사용합니다. 노드 검사는 우클릭 Edit 또는 Selected Node Edit에서 별도 창으로 엽니다. Summary에서 Node ID·Real ID·UID와 Port ID를 검색하며 미니맵 클릭으로 이동합니다. Hide Menu는 상단·왼쪽·하단 패널을 접습니다. 3D 화면의 제작·배치 구성은 별도로 유지합니다.

상단의 2D와 3D에서 동일한 지도 도형과 라벨 및 표시 옵션을 공유합니다. 다크 모드와 라이트 모드는 화면과 지도에 함께 적용됩니다. Electron은 원본 MAP 폴더의 JMAPX에 대응하는 DATA/파일명_port_group.bem도 함께 읽어 포트 그룹 외형을 반영합니다. 2D의 일반 왼쪽 드래그는 영역 선택이며 스페이스를 놓으면 이동 모드가 해제됩니다. Space를 누른 상태에서 왼쪽 마우스로 드래그하면 지도가 이동하며, 3D의 오른쪽 드래그는 시점 회전이며 일반 왼쪽 클릭은 선택과 배치입니다. 3D 이동은 TS_UI와 같은 바닥 기준 패닝을 사용하여 카메라와 회전 중심의 높이를 유지하며, 회전 시 지면 아래로 내려가지 않도록 각도를 제한합니다.

상단 열기는 두 모드에서 기준 지도를 교체합니다. 지도 교체 시 선택과 편집 이력 및 기존 3D 설계를 초기화하며, 저장하지 않은 변경은 교체 전에 확인합니다. 3D 설계를 다시 열려면 3D 화면의 설계 프로젝트 열기를 사용합니다.

## 지도 표시 품질과 검증

원형 노드의 기본 반경은 TS_UI와 동일한 25mm이며 곡선 노드의 원형 마커와 방향 마커는 같은 화면의 단위를 환산합니다. 지도 객체는 명시적인 앞뒤 순서로 그려 겹친 면의 깜빡임을 방지하고, 큰 현장 좌표는 렌더링에만 지역 좌표를 사용하여 원본 파일 좌표를 유지합니다.

이동 중 라벨 목록과 도형을 재사용하며 6px 미만의 라벨은 확대했을 때 표시합니다. 3D 라벨 캔버스는 화면 배율을 반영하고 크기가 바뀔 때만 재할당합니다. 설비의 외곽 상자로 가려지는 바닥 라벨은 표시하지 않으며, 표시 옵션 변경으로 설비 모델을 다시 생성하지 않습니다.

`node scripts/test-map-rendering.mjs`는 8,000개 노드와 800개 포트의 브라우저 렌더링, 치수, 대형 원점 좌표, 라벨 재사용, 설비 가림과 고해상도 캔버스를 검증합니다. 선택적으로 JMAPX 파일 경로를 인자로 넘겨 실제 지도도 확인할 수 있습니다. 스크린샷은 임시 폴더에 생성합니다.

## 원본 지도 열기와 저장

JMAPX Ver.23과 Ver.25는 원본 제어 레코드를 유지한 채 편집합니다. **열기**는 개별 지도 파일을 선택하며, **Project Select**는 RCS 또는 MAP 폴더에서 시간 기반 파일명이 가장 최신인 지도를 엽니다. 인접 SETTING/Theme.INI와 DATA/파일명_port_group.bem을 함께 읽습니다.

**Map Save / Save**와 Ctrl+S는 원본 지도에서 저장 항목 창을 엽니다. Bay·Bay Group·Zone·Offset·Port Limit, Around 생성 반경, AES 생성 여부와 차량 치수를 선택합니다. 원본 MGS처럼 MAP/YYYYMMDD_HHmmss.jmapx를 새로 생성하고 포트 그룹 및 영역과 Around는 같은 이름의 DATA/파일명_항목.bem으로, AES는 DATA/TRAFFIC/파일명.aesx로 저장합니다. 부가 파일을 먼저 확정하고 지도를 마지막에 공개하며 실패하면 이번 저장에서 만든 파일만 복구합니다. 기존 버전은 유지하고 같은 시각의 이름은 중복을 피합니다. **Save Only Map**은 운행 부가 데이터 재생성을 제외하며, 영역 설정을 저장에서 제외한 경우 해당 변경까지 저장 완료로 표시하지 않습니다. **Save As** 또는 Ctrl+Shift+S는 대상 RCS 또는 MAP 폴더를 선택합니다. 새 지도도 JMAPX 형식으로 시작합니다. 기존 TS_MGS JSON을 열었다면 JSON 형식을 유지합니다.

하단 **Selected Port Edit / Selected Path Edit** 또는 속성창의 **객체 편집**에서 포트의 위치·크기·표시 속성, 연결 경로의 방향·거리·속도, 도형의 치수·종류·표시 속성을 수정합니다. 포트와 도형의 추가·삭제도 지원합니다. 다른 포트의 부모·대기·예약 목록에서 참조 중인 포트 삭제는 연결 데이터 정리를 요구합니다. 적용한 변경은 실행 취소·다시 실행 대상이며 원본에서 해석하지 않는 제어값과 예약 필드는 그대로 보존합니다. JMAPX의 좌표와 크기는 정수 mm입니다.

상단 **[E] Edit Port** 또는 E 키로 포트 편집 모드를 전환합니다. 포트 우클릭 메뉴에서 추가·편집·삭제와 앞뒤 정렬을 실행합니다. View의 기본 식별자·좌표·거리·반지름·포트 이름과 ID 표시를 지원하며 Shape 탭의 도형은 지도 드래그로 생성합니다.

**Selected Node Edit**에서 선택 또는 전체 노드의 속성과 플래그, 상대 이동, 직선 간격 분할, 방향별 경로 제어값, Real ID 순서와 삽입, 연결 구조 복제와 삭제, 격자 생성 및 경로 거리를 편집합니다. 중간 노드 삭제 시 로컬 ID와 연결 참조를 함께 재정렬하며 UID와 Real ID를 유지합니다. Removable과 Changeable 설정을 반영하고, 곡선 이동은 원본 선택 이동의 연결 방향을 따라 보간 노드를 함께 이동합니다. 사행·직각·Crab 주행은 기준 직선을 따라 차량 각도를 다시 계산하며 기준 없는 순환 연결은 오류로 표시합니다. 포트의 운행 속성 및 여덟 예약 UID 목록, Bay 목록과 포트 그룹 추가·편집·삭제를 지원합니다. 직선 간격 분할은 끝점과 분기를 유지하며 마지막 구간은 지정 간격보다 짧을 수 있고 기존 곡선을 다시 표본화하지 않습니다.

Bay / Zone 설정은 다섯 종류의 표를 편집하고 삭제된 행의 지도 참조를 정리합니다. 주변 노드 검사는 지정 거리 이하의 객체를 선택합니다. Bay 필터와 포트 인덱스·UCS 인덱스, 캡션 인출선, 테마 글꼴 크기, 렌더링 일시 정지를 제공합니다. Teaching은 XLSX/CSV에서 Real ID 기준 좌표·Offset·차량 각도·ODS·속도·포트 설정을 읽고 유효한 선택 행만 한 번에 적용합니다. XLSX 해석은 브라우저 ZIP 해제와 XML 해석으로 구성합니다. AES는 원본 `g_aes_mgs.cs`의 외곽 표본, 현재 위치와 다음 위치의 분리 충돌, 합집합과 빈 ALL 목록 규칙을 포팅했습니다. AGV_TYPE.INI를 선택하면 AGV_TYPE_01의 차량 치수를 읽습니다.

Control Map Data에서 회전 가능 플래그의 전체 설정과 해제, IC / JC 회전각 기준 자동 설정, 포트 노드의 회전 해제, No Send Goal의 단방향 교차 자동 설정과 Don’t Remove CMD의 양방향 자동 설정을 제공합니다. 경로 인덱스 재생성 명령은 차량 각도와 역방향 참조도 갱신합니다. 저장 계산 결과의 거리·각도·포트 UID는 편집 문서에도 즉시 반영하고 새 포트 UID는 다른 포트를 삭제해도 유지합니다.

전체 MGS 기능 이관은 진행 중입니다. 원본 리본 107개 명령 중 연결되지 않은 22개 명령은 비활성 상태이며, 연결 여부가 해당 기능의 모든 세부 동작에 대한 동등성 검증 완료를 뜻하지 않습니다. 다음 항목은 아직 이관 또는 검증이 필요합니다.

- Feature·Blocking·Pre-Occupation 생성과 편집, Command·SCMD·Schedule·Vehicle Limited Area와 DPP
- AGV·Carrier·Contour·ODS·Grid·Drawing 설정 창과 SETTING 파일 저장 및 다른 프로젝트로 복제
- 원본 불법 노드·포트 상세 진단 및 수정, LOT 거리, IC / JC, 제외 Occupation과 AES 상세 조회
- 차량 방향 도형, 곡선 시작 노드 강제 삭제, 기존 곡선 연결 재구성과 곡선 그래프 복제, 직각 주행 자동 Reverse 전파
- DB 데이터 적용과 Ver.23 이전 파일 변환
- 원본 C#에서 생성한 현장 AES·Around 파일과의 전수 대조 및 원본 저장 마법사 전체 단계

Verify의 문서 구조 검증과 생성된 AES 파일의 회귀 검사는 원본 운행 검증 전체를 대신하지 않습니다. 이관 검사는 `node scripts/check-mgs-migration.mjs`, `node scripts/check-teaching.mjs`, `node scripts/check-area-save.mjs`, `node scripts/check-aes.mjs`로 실행합니다. `MGS_REFERENCE_MAP` 환경 변수로 실제 JMAPX를 지정하면 읽기 전용으로 원본 무변경 보존과 포트 설정의 저장 복원도 검사합니다. 검사와 개발 과정에서 원본 MGS 소스 및 현장 프로젝트 파일을 수정하지 않습니다.

## 3D 데이터 제작

기존 2D JMAPX 또는 TS_MGS JSON을 열고 **3D**로 전환합니다. **새 모델 디자인**에서 박스·원통 부품을 조합해 직접 모델을 만듭니다. 랙·선반·컨베이어는 빈 모델에서 선택하는 시작 도면이며, 생성한 모든 부품은 이름·위치·치수·축별 회전·색상과 구성을 자유롭게 수정할 수 있습니다. 제작 화면에서 부품을 클릭하고 이동·회전·크기 핸들로 편집하거나 수치를 입력합니다. 복제·간격 지정 반복 배치·바닥 정렬과 제작 이력의 실행 취소·다시 실행을 지원합니다.

부품 목록의 체크박스로 여러 부품을 고른 뒤 **좌표 일괄 편집**에서 변경할 X/Y/Z 축만 체크합니다. **상대 이동**은 간격을 유지한 채 입력 거리만큼 이동하며, **값 지정**은 해당 축을 같은 절대 좌표로 맞춥니다. 전체 선택과 검색 결과 선택 및 Ctrl+A를 지원하고, 일괄 좌표 변경은 실행 취소 한 번으로 되돌릴 수 있습니다. 체크 대상은 제작 화면에서 강조되며 개별 부품 선택과 독립적으로 유지됩니다.

모델을 라이브러리에 적용한 뒤 포트를 클릭하거나 Port ID를 선택해 한 개씩 배치합니다. **선택 모델 편집**은 같은 모델의 기존 배치에도 반영하며, **새 모델로 저장**은 기존 모델을 유지하는 별도 모델을 만듭니다. 적용 전 초안은 기존 배치에 영향을 주지 않습니다. 기존 프로젝트의 모델도 부품 단위로 편집할 수 있으며, 배치별 위치·높이·회전은 지도 화면에서 조정합니다.

**설계 프로젝트 저장**은 모델과 배치를 함께 저장하며 다시 열어 편집할 수 있습니다. **3D 데이터 추출**은 선택 폴더 안에 새로운 하위 폴더를 만들고 다음 두 파일을 저장합니다.

- `equipment.json`: 재사용 가능한 설비 모델과 부품 형상
- `map3d.json`: 기준 맵·모델 ID·포트 ID·포트 기준 오프셋·회전·절대 좌표 캐시

기존 2D JMAPX는 별도로 유지합니다. TS_UI에서 같은 2D 맵을 열고 3D 모드의 **3D 배치·설비 파일 열기**에서 두 JSON을 함께 선택합니다. 포트 연결 배치는 현재 포트 위치에 오프셋을 더해 그립니다. 파일 좌표는 mm, MGS XY 바닥/Z 높이 기준입니다.

`@bem/map3d`의 TS_UI 의존성은 `../TS_MGS/packages/map3d` 경로를 사용하므로 해당 공유 패키지를 함께 유지해야 합니다.

## 코드 작성 기준

소스 내부의 import와 export 및 동적 import는 src를 가리키는 `@/` 별칭을 사용합니다. 다른 슬라이스는 공개 index.ts를 통해 참조합니다.

함수는 const 화살표 함수로 선언하고 함수 설명과 매개변수 및 반환값은 JSDoc으로 작성합니다. 일반 처리 설명은 단일 행 주석을 사용하며, 주석 설명은 채번과 장식 기호 없이 명사형 단어로 끝냅니다. 소스 파일 헤더에는 파일명과 설명 및 작성자와 작성일자를 기록합니다. JSON 설정 파일은 표준 형식 유지를 위해 주석을 포함하지 않습니다.

Vuetify의 컴포넌트와 유틸리티 클래스를 우선 사용합니다. 화면별 고유 스타일은 해당 Vue 컴포넌트의 scoped SCSS에 작성하며, 루트 컴포넌트에는 색상 토큰과 최소 공통 스타일만 둡니다.
