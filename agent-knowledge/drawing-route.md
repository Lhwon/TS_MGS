# 도면 기반 맵 설계

도면으로 새 맵을 설계할 때 입고·보관·출고와 같은 운행 흐름을 먼저 확인한다. 이미 그려진 통로 색상의 복원이 목적이면 generate_drawing_map을 사용한다. 벽과 문만 있는 도면에 새로운 주행 동선을 설계하는 요청이면 inspect_drawing으로 도면을 읽고 plan_drawing_route를 사용한다.

1. 가로와 세로 치수선의 양 끝을 읽어 각각 기준 길이와 짝지어 적용한다. 영상에서 검출된 치수선은 inspect_drawing의 픽셀 검증을 통과한 후보만 사용하고 cross를 그대로 전달한다. 검출된 선의 숫자를 확신할 수 없으면 ask_user로 확인한다. 치수선이 한 축에만 있으면 두 축에 같은 비율을 적용한 초안임을 보고한다. 근거가 없는 치수는 비워 픽셀 초안을 만든다. 사용자가 실제 치수 작업을 원한다면 확인 가능한 기준 길이만 물어본다.
2. 사용자 요청에 맞는 입고와 출고 정차점을 먼저 잡는다. 문이 여러 개라면 위치와 함께 선택지를 제시한다. 이미지 밖이나 벽 위에 정차점을 두지 않는다.
3. 주행 순서로 중심선의 꼭짓점을 설계한다. 통로가 충분한 곳에 회차 구간을 두고 벽과 설비의 경계는 금지 영역으로 사용한다. 알려진 차량 폭과 여유를 반영한다. 정확한 폭이나 회전반경이 없는 경우 현장 검토값으로 남긴다.
4. 랙마다 중심선에 접속하는 지점과 랙 앞 접근점 및 랙 외곽을 지정한다. 층수가 확인되면 같은 접근 노드에 층별 포트를 붙인다. 사용자가 요청한 층수를 랙 개수로 해석하지 않는다.
5. 도구가 직선을 최대 간격 기준으로 분할하고, 충분한 길이가 있는 코너에서 접선 곡선을 만든다. 결과에는 입고에서 랙 접근점, 접근점에서 출고까지의 방향성 검증과 장애물 교차 검사를 포함한다.
6. 생성과 수정은 열린 편집기의 미저장 문서에 적용한다. 사용자가 먼저 저장하라고 하더라도 저장 UI에서 대상 위치와 항목을 확인해 직접 실행하도록 안내한다.

## 쇼룸 검증 사례

쇼룸에서는 도면에서 읽은 가로 15,000 mm와 세로 21,400 mm를 각각 기준으로 사용했다. 하단 좌측 입고 후보에서 좌측 랙을 따라 올라가 상부에서 회전한 뒤 우측 출고 후보로 향하는 주행선을 설계했다. 각 랙의 네 층에 같은 접근 노드를 공유하는 포트를 두었다. 기존 MGS 저장 형식으로 변환한 뒤 경로 레코드를 다시 읽어 점검했다. 이 치수와 배치는 쇼룸의 검증 사례이며 다른 도면의 기본값으로 사용하지 않는다.
